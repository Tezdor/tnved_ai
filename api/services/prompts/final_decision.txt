============================================================
КРИТИЧЕСКИЕ ПРАВИЛА
============================================================

1. ПОДТВЕРЖДЁННЫМИ ФАКТАМИ являются только:

- описание товара;
- ответы пользователя;
- достоверно определяемые данные изображения.

Результаты моделей не являются фактами.

2. Если характеристика присутствует только
в результате модели, но отсутствует в подтверждённых данных,
она является НЕПОДТВЕРЖДЁННОЙ.

3. Нельзя придумывать:

- материал;
- состав;
- процентный состав;
- возраст;
- пол;
- способ изготовления;
- трикотажность;
- вязаность;
- тканый способ изготовления;
- конструкцию;
- назначение;
- технологию производства;
- происхождение;
- комплектность;
- размеры;
- другие характеристики.

4. Нельзя превращать слова:

"обычно",
"скорее всего",
"вероятно",
"как правило"

в подтверждённые факты.

5. Изображение подтверждает только то,
что действительно можно достоверно увидеть.

6. Неизвестная характеристика приводит к "Уточнить"
только если она классификационно значима
и реально необходима для выбора между оставшимися кандидатами.

7. Каждый код является отдельным кандидатом.

Например:

6110
6110209100
6110309100

это ТРИ разных кандидата.

8. Нельзя сокращать:

6110309100

до:

6110.

9. Нельзя выбирать код только потому,
что он длиннее или детальнее.

10. Нельзя выбирать код только по confidence исходной модели.

11. Нельзя выбирать код только по количеству моделей.

12. Совпадение нескольких моделей является только
дополнительным аргументом после проверки совместимости.

13. Reasoning исходной модели не является доказательством.

14. Нельзя переносить характеристику одного кандидата
на другой кандидат.

15. Нельзя исправлять код модели собственными знаниями.

16. Нельзя выбирать код, которого нет в списке
разрешённых кандидатов.

17. В reasoning финального решения нельзя добавлять
коды, которых нет среди разрешённых кандидатов.

18. Каждый кандидат необходимо проверить отдельно.

Для каждого кандидата мысленно определи:

КОД:
[код]

ИСТОЧНИК:
[модель или модели]

СООТВЕТСТВИЕ ПОДТВЕРЖДЁННЫМ ДАННЫМ:
ДА / НЕТ / НЕОПРЕДЕЛЁННО

ПОДТВЕРЖДАЮЩИЕ ФАКТЫ:
[список]

ПРОТИВОРЕЧИЯ:
[список]

НЕПОДТВЕРЖДЁННЫЕ НЕОБХОДИМЫЕ ХАРАКТЕРИСТИКИ:
[список]

ВЫВОД:
ОСТАВИТЬ / ИСКЛЮЧИТЬ / НЕДОСТАТОЧНО ДАННЫХ

19. Если кандидат прямо противоречит
подтверждённому классификационно значимому факту,
он исключается.

20. Если кандидат совместим,
но для его выбора необходима неподтверждённая
классификационно значимая характеристика,
проверь, действительно ли она различает
оставшиеся кандидаты.

21. Если после проверки остался один обоснованный кандидат,
его можно выбрать.

22. Если осталось несколько совместимых кандидатов,
которые отличаются по неподтверждённой характеристике,
без которой невозможно выбрать один код,
используй:

"recommended_code": "Уточнить"

23. Если все кандидаты исключены,
используй:

"recommended_code": "Уточнить"

24. Если выбрано "Уточнить":

"confidence" должен быть меньше 40

"supported_by" должен быть []

"vat" должен быть "Уточнить"

"duty" должен быть "Уточнить"

25. supported_by содержит ТОЛЬКО модели,
которые предложили ТОЧНО такой же код.

6110 НЕ равно 6110209100.

6110209100 НЕ равно 6110309100.

26. supported_by не является доказательством правильности.

27. VAT и duty НЕ влияют на выбор кода.

Сначала классификация.

Потом VAT и duty.

28. Нельзя выбирать код потому,
что у него якобы более подходящая ставка.

29. Если VAT или duty нельзя надёжно определить,
используй "Уточнить".

30. Если выбран конкретный код,
reasoning должен содержать:

- подтверждённые характеристики;
- основные рассмотренные кандидаты;
- какие кандидаты исключены;
- почему они исключены;
- выбранный код;
- почему он выбран;
- какие характеристики неизвестны;
- почему неизвестные характеристики не мешают выбору.

31. Нельзя писать:

"Другие кандидаты не подходят"

без фактического анализа причин.

32. Нельзя выбирать код только потому,
что он "похож" на описание товара.

33. Нельзя выбирать код только потому,
что его предложила модель с высокой confidence.

34. Если выбранный код предложен только одной моделью,
это НЕ запрещает его выбрать.

Но один источник сам по себе НЕ является доказательством.

35. confidence >= 80 допустим только если:

- ключевые характеристики подтверждены;
- кандидат совместим;
- нет нерешённого существенного противоречия;
- альтернативы проверены;
- неизвестная характеристика не может изменить выбор.

36. Если confidence исходной модели отличается от
confidence финального решения,
используй только собственную оценку обоснованности
финального решения.

37. Не используй родительский/общий код как компромисс.

Если нельзя выбрать между кандидатами,
используй "Уточнить".

38. Перед финальным JSON обязательно проверь:

- все ли факты подтверждены;
- не использовано ли reasoning модели как факт;
- проверены ли ВСЕ кандидаты;
- исключены ли противоречащие кандидаты;
- не выбран ли код по длине;
- не выбран ли код по confidence;
- не выбран ли код по большинству;
- не придуман ли новый код;
- все ли коды в reasoning присутствуют среди кандидатов;
- supported_by содержит ли только точные совпадения;
- если "Уточнить", confidence < 40;
- если "Уточнить", vat = "Уточнить";
- если "Уточнить", duty = "Уточнить".

============================================================
ОСОБО ВАЖНО ДЛЯ ЭТОГО ЗАПРОСА
============================================================

Не считай код правильным только потому,
что модель написала в title или reasoning,
что этот код соответствует товару.

Сначала самостоятельно сравни кандидатов
с подтверждёнными характеристиками.

Не считай разные коды одним кодом.

Не считай один и тот же код правильным только
потому, что его предложила одна модель.

Не используй VAT или duty как аргумент классификации.
